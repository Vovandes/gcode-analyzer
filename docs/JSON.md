# JSON анализа, схема 1

## Добавления этапа 12 (0.12.0)

- `tools[].diameterMm` содержит диаметр из секции `( TOOL LIST: )` либо `null`. H/D и диапазоны осей берутся из существующих `hValues`, `dValues` и `box`.
- `tools[].detail.motionTime` содержит время движения в секундах по действующей модели, включая рабочие ходы, G0, циклы и выдержки. Время смены, G28/G30, отдельное время индексной B и запуск шпинделя относятся к общему `machineTime`.
- `tools[].detail.workingMm` и `idleMm` включают рабочие и ускоренные части моделируемых циклов. `feedMmPerMin` и `rpm` — диапазоны действующих F/S во время рабочих ходов. G95 переводится в мм/мин при известных оборотах. Неизвестный диапазон записывается как `null`.
- `toolTotals.detail` содержит суммы времени и длин и объединённые диапазоны F/S. Первые три элемента `toolTotals.box` дают общий диапазон X/Y/Z в рабочей СК.
- `warnings` может содержать W029–W036. Старые коды и поля схемы 1 сохраняются.

## Добавления этапа 11б (0.11.1)

Схема остаётся 1. Прежние поля Fanuc сохранены. У GNC62 могут появляться:

- `segments[].a`, `c`: конечные углы в градусах либо `null`; добавляются при наличии данных/задания A/C. XYZ в `start/end` сохраняют прежний формат из трёх чисел.
- `approximate:true`: XYZ представляют номинальную геометрию при преобразовании/RTCP/точении; GUI показывает её без расчёта кинематики. `surfaceSpeed:true`: S выражает скорость резания, `spindle` не выдаётся за RPM. `spindleChannel`: номер активного шпинделя, когда он отличается от текущего (0).
- `tools[].name`: исходное строковое имя инструмента. `tool` — внутренний числовой ключ выше всех числовых T этого файла, без претензии на номер магазина. `box/workBox` по-прежнему содержат X/Y/Z/B; если известны A/C, добавляются два диапазона: **X/Y/Z/B/A/C**.
- Корневой `header:{tools:[строки],operations:[строки]}` присутствует, если в шапке найдены соответствующие списки.
- A/C в `limits` выражены в градусах; пустые границы C/B не создают проверки. GNC62 G53 может давать машинные сегменты без геометрического профиля. Для номинально преобразованных XYZ абсолютные проверки пропускаются с W027. После измерения с записью СК старые смещения XYZ не используются.

| Код | Уровень | Проверка |
|---|---|---|
| W023 | `error` | Незавершённый GDEF перед GCALL, отсутствующий обязательный адрес, E ≤ 0 у G923/G924/G933 |
| W024 | `error` | Цикл касания / `prb_xyz` требует G94 |
| W025 | `warning` | Известный дефект предоставленных G932/G934/G935/G960; установленную версию следует проверить |
| W026 | `info` | Последствия измерения: смена/запись СК, G28, неизвестное конечное положение и нерассчитанные внутренние ходы |
| W027 | `info` | Неполная модель макросов, преобразования, интерполяции, специфической подачи или пути G28 GNC62 |
| W028 | `info` | Признаки GNC62 при выбранном Fanuc: «похоже на GNC62, используйте --dialect gnc62» |

Измерительные GDEF/GCALL не создают выдуманных сегментов касания или отверстий Fanuc. Неполная оценка сообщается через предупреждения и `machineTime.notes`. Подробности: [GNC62.md](GNC62.md).

## Основные поля

`gcode-analyzer.exe программа.nc --out отчёт.txt --json анализ.json` выполняет анализ один раз. JSON — UTF-8 без BOM, переводы строк LF, вещественные числа с точкой и четырьмя знаками после неё. `--bom` влияет только на TXT. Номера строк начинаются с 1. Выходной JSON не должен совпадать с входным файлом или TXT (ошибка аргументов, код 2); ошибка записи — код 1.

Верхние поля:

| Поле | Содержимое |
|---|---|
| `schema` | Версия схемы, целое `1` |
| `file` | `name`, `lines`, `blocks`, `dialect` (id), `machine` (из комментария), `machineProfile` (выбранный профиль), `rapidFeed` в мм/мин |
| `segments` | Все события движения в исходном порядке, включая выдержки и возвраты |
| `warnings` | `line`, `code`, `severity`, `message`, `text` |
| `tools` | Данные существующей модели `ToolReport`, в порядке модели отчёта |
| `time` | Общие времена, длины и счётчики |
| `limits` | Массив проверок пределов станка (расширение этапа 11) |
| `machineTime` | Новая оценка времени, разбивка и ограничения (расширение этапа 11) |

Сегмент содержит `line`, `kind` (`rapid`, `linear`, `arc`, `cycle`, `dwell`, `home`), `tool` (0 до выбора инструмента), `plane` (`G17`, `G18`, `G19`), `start` и `end` — массивы `[X,Y,Z]` в мм, `null` для каждой неизвестной оси. Значение `b` — модальный угол B в конце события, в градусах, либо `null`.

`feed` — эффективная подача в мм/мин: для G95 это F×S, для G0 — настройка `--rapid`; у выдержки, возврата и неизвестной/нулевой рабочей подачи — `null`. `spindle` — модальное заданное S в об/мин или `null`, если S ещё не задано; остановка M5 сама по себе не сбрасывает заданное S.

Дуга дополнительно содержит `center:[X,Y,Z]`, `cw` и `radius`. Центр абсолютный, третья ось берётся из начальной точки (у винтовой дуги начало и конец могут иметь разную высоту). При невозможности вычислить дугу центр — `[null,null,null]`, радиус — `null`; направление сохраняется. Причина — в предупреждениях W018. Плоскость и направление соответствуют геометрии `planeAxes`: G17 — XY, G18 — ZX, G19 — YZ.

У `dwell` есть `dwellSec`. У `cycle` есть объект `cycle`: `code`, `zR`, `zBottom`, `zInit` (либо `null`), `q`, `p` (либо `null`), `returnToInitial`. `start/end` цикла описывают положение до и после полного цикла; дно отверстия берётся из `zBottom`. Один кадр может дать несколько событий (позиционирование G0 и цикл). У `home` конечная координата оси известна только при заданной референтной точке и смещении рабочей СК; иначе `null`.

`limitViolation:true` добавляется к сегментам с нарушением пределов и задаёт красную обводку в окне; отсутствие поля означает `false`. Для G53 с геометрическими данными профиля есть `machineCoordinates:true`, `start/end` в машинных координатах, а `workStart/workEnd` — координаты той же линии в рабочей СК для визуализации (неизвестные оси — `null`). Окно не пересчитывает смещения. Без геометрических данных профиля сохраняется прежняя обработка G53 без сегмента.

`time` и `tools[].time`: `totalSec`, `rapidSec`, `feedSec`, `cycleSec`, `dwellSec` — секунды; `rapidMm`, `feedMm`, `cycleMm` — мм; `rapidMoves`, `feedMoves`, `cycleHoles` — целые счётчики. Это прежняя модель без разгонов и времени поворота B.

`tools[]`: `tool`, `descriptions`, `changes`, `changeLines`, `hValues`, `dValues`, `time`, `box`, `workBox`, `feedPerMin`, `feedPerRev`, `spindle`, `fractionalS`, `spindleDirs`, `coolant`, `wcs`, `cycleHoles`. Диапазон — `{min,max}` или `null`; габариты — четыре диапазона в порядке X/Y/Z/B. `cycleHoles` — объект «код цикла → число отверстий». Сохраняются все инструменты существующего отчёта, включая запись T0, если она была создана анализаторами до первой смены.

`limits[]`: `parameter`, `valueMin`, `valueMax`, `limitMin`, `limitMax`, `status` (`ok|error|info`), `line`. Числа отсутствующих границ — `null`. F в мм/мин (для G95 — F×S), S в об/мин, XYZ в мм, B в градусах. Без смещения соответствующей оси проверяется только размах в пределах каждой СК; статус `info` не означает, что абсолютные координаты безопасны. Превышение размаха даёт `error`. В TXT выводятся те же значения и строки. Пустой массив означает, что проверки не выполнялись либо отсутствуют данные.

`machineTime`: `totalSec`, `accelerations` (хотя бы часть движений рассчитана с ускорением), `profileApplied`, `motion` (та же структура, что `time`), `toolChangeSec`, `homeSec`, `bSec`, `spindleSec`, `programStops`, `optionalStops`, `notes`. Итог равен сумме `motion.totalSec` и четырёх дополнительных времён. Выдержки циклов входят в `motion.dwellSec`; старая `time.cycleSec` по-прежнему включает их. M0/M1 не добавляют неизвестное время оператора в итог. `notes` перечисляет отсутствующие параметры и частичные оценки. Без ускорений явно записано «оценка без ускорений», без профиля — причина неприменения новой модели. Подробные формулы: [MACHINE_PROFILES.md](MACHINE_PROFILES.md).

Уровни заданы только в `include/gca/analyzers/warnings.hpp`:

| Уровень | Коды |
|---|---|
| `error` | W004, W005, W008, W009, W010, W011, W016, W017, W018, W019, W020, W021, W023, W024 |
| `warning` | W001, W002, W003, W006, W007, W012, W014, W025 |
| `info` | W013, W015, W022, W026, W027, W028 |

W019 — превышение максимальной рабочей подачи; W020 — превышение максимальных оборотов; W021 — выход за пределы оси либо превышение хода по размаху; W022 — абсолютные пределы не проверены из-за отсутствующих смещений СК.

Потребителю следует проверять `schema`; неизвестные дополнительные поля можно пропускать. Потеря обязательных данных или неподдерживаемая версия в окне показываются как ошибка чтения JSON.

## JSON сравнения

`--compare old.nc new.nc --json comparison.json` создаёт объект с `schema:1` и `kind:"comparison"`.

| Поле | Содержимое |
|---|---|
| `tolerance` | Допустимое расстояние XYZ в мм |
| `before`, `after` | `file`, `segments` и `warnings` старой и новой УП в описанном выше формате. Геометрия выводится с полной точностью чисел ядра |
| `summary[]` | `label`, `before`, `after`, `difference` — строки для таблицы. `trend` равен `neutral`, `improved` или `worsened` |
| `trajectory[]` | `tool` — подпись инструмента. `presence` — `both`, `added` или `removed`. `oldPoints` и `newPoints` — количества конечных точек |
| `trajectory[].differenceCount` | Общее число расхождений для общего инструмента |
| `trajectory[].differences[]` | Первые 20 расхождений. `kind` — `modified`, `inserted` или `deleted`. `oldLine` и `newLine` — номера строк от 1. Отсутствующая сторона — `null` |
| `format[]` | Изменившиеся группы шпаргалки. `label` — подпись группы, `before` и `after` — массивы строк |
| `newWarnings[]`, `resolvedWarnings[]` | Новые и исчезнувшие предупреждения с номером строки, исходным кадром, кодом, сообщением и уровнем |

Признак улучшения или ухудшения применяется к времени и количеству диагностик. Подачи, обороты и остальные показатели показывают величину изменения нейтральным цветом. Для добавленных и пропавших инструментов `differenceCount` равен 0, а `differences` пуст.

В сопоставлении участвуют конечные точки перемещений, включая положение после цикла. Сравниваются известные оси XYZ, а поворотные оси проверяются с точностью 10⁻⁹ градуса. При доступных смещениях для G53 используются рабочие координаты. Наложение использует полные сегменты и геометрию дуг. Предупреждения сопоставляются по коду и сообщению с учётом числа повторов.
