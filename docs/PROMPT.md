# Промпт для Claude Code

Скопируй текст ниже в Claude Code, запущенный в корне репозитория `gcode-analyzer`.

---

Ты работаешь в репозитории `gcode-analyzer` — анализатор управляющих программ Fanuc (фрезерование, 3 оси + индексная ось B) на C++20 / CMake. Сейчас в репозитории только каркас: сборка, CI, заглушки и документация. Твоя задача — реализовать анализатор.

1. Сначала прочитай `CLAUDE.md` и **полностью** `docs/SPEC.md`, затем `REPORT.md`. Строго соблюдай правила из `CLAUDE.md`.
2. Реализуй этапы из `docs/SPEC.md` (раздел 7) **по порядку**: этап 1 → 2 → 3 → 4 → 5. Переходи к следующему этапу только когда выполнены все критерии приёмки текущего.
3. Архитектура — как в разделе 6 SPEC: лексер, профиль диалекта (`IDialect` + `FanucMillDialect`), точка расширения `ICodeKnowledgeProvider` (только интерфейс + встроенная таблица, онлайн-поиск не реализовывать), модальная машина состояний, расчёт перемещений и времени, набор анализаторов-наблюдателей, модель отчёта + текстовый writer, тонкий CLI. Всю логику держи в библиотеке `gca_core`.
4. Учитывай реальные особенности формата из раздела 5 SPEC: CRLF, слитные слова (`G05.1Q0`, `T1M6`, `M6T4`), предвыбор T, винтовые дуги и полные окружности через I/J, G95 в циклах, `G91 G28`, дробные S, N только в начале операций, машинно-специфичные M15/M53/G05.1/G08. Ось B в образцах отсутствует — проверяй её на синтетических программах в `tests/data/`.
5. После **каждого** изменения: `cmake --preset debug && cmake --build --preset debug && ctest --preset debug`. Если красное — чини, пока не станет зелёным. Не ослабляй тесты. Код должен собираться и на MSVC (не используй непортируемые конструкции).
6. Файлы в `samples/` не изменяй ни при каких условиях.
7. После каждого этапа: обнови `REPORT.md` (что сделано, как собрать, результаты тестов с числами, проверка на образцах, известные проблемы, следующие шаги), сделай коммит с понятным сообщением (`stageN: ...`) и `git push`.
8. В конце работы запусти анализатор на обоих образцах с `--out` и кратко опиши в `REPORT.md`, что показала шпаргалка для постпроцессора. Если что-то в SPEC неоднозначно — прими разумное решение, зафиксируй его в `REPORT.md` в разделе «Известные проблемы и ограничения» и продолжай.

Если лимит сессии заканчивается — остановись на завершённом, зелёном состоянии, обнови `REPORT.md`, закоммить и запушь, чтобы следующую сессию можно было продолжить с того же места.
