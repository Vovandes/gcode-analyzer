# Профили станков и оценка времени

CLI ищет INI-файлы в `machines/` рядом со своим exe, независимо от текущей папки. CMake копирует эту папку рядом с собранным CLI при обычной сборке; `package.ps1` включает её в оба варианта архива. `--list-machines` возвращает встроенные и файловые профили. Файл `<id>.ini` дополняет/переопределяет встроенный профиль с тем же id; новый id добавляется в список. При `--machine auto` используется непустой `match` в комментарии `Generated for ...` без учёта регистра ASCII и пробелов.

`--machine-file <путь>` явно выбирает файл и имеет приоритет над `--machine` и автоопределением. Если файл имеет id уже загруженного профиля, он дополняет этот профиль. Приоритет: встроенный → соседний `machines/<id>.ini` → `--machine-file` → `--wcs-offset`. Пустой ключ явно очищает унаследованное значение; отсутствующий ключ сохраняет его. Учитываются только известные данные. Неизвестный ключ, секция, повтор ключа, неправильное число или диапазон дают ошибку аргументов (код 2) с именем файла и физическим номером строки. Ошибка чтения файла/каталога — код 1.

INI — UTF-8, допускается BOM, LF/CRLF. Один `ключ = значение` на строку. Комментарии `;` и `#` продолжаются до конца строки, включая комментарии после значения; кавычки и экранирование не поддерживаются. Регистр ключей значим. В начале файла вне секций допустимы `name` и `match`. Все параметры, кроме служебных умолчаний угла и флага первой смены, необязательны. Числа конечные, с точкой; скорости и ускорения строго положительные, времена неотрицательные. Минимум оси не может превышать максимум.

## Ключи

| Секция | Ключи | Единицы и смысл |
|---|---|---|
| вне секций | `name`, `match` | Название и подстрока автоопределения; id берётся из имени файла |
| `[axes]` | `x_min`, `x_max`, `y_min`, `y_max`, `z_min`, `z_max`, `b_min`, `b_max` | Машинные координаты: XYZ в мм, B в градусах |
| `[axes]` | `x_home`, `y_home`, `z_home`, `b_home` | Референтная точка G28, машинные координаты |
| `[axes]` | `x_home30`, `y_home30`, `z_home30`, `b_home30` | Отдельная референтная точка G30; не подменяется G28 |
| `[axes]` | `G54` … `G59` | Например `G54 = X10Y20Z-100`; машинная позиция = программная + смещение |
| `[limits]` | `feed_max`, `spindle_max` | Рабочая подача мм/мин; обороты об/мин |
| `[time]` | `rapid_x`, `rapid_y`, `rapid_z` | G0 по отдельным осям, мм/мин; пропущенная скорость использует `--rapid` |
| `[time]` | `accel_x`, `accel_y`, `accel_z` | Ускорения мм/с² |
| `[time]` | `tool_change` | Время одной смены, с |
| `[time]` | `skip_first_change` | `true`/`false`, по умолчанию false; true означает, что первый инструмент уже установлен |
| `[time]` | `b_seconds_per_90` | Секунд на 90° индексной оси B |
| `[time]` | `spindle_start` | Секунд на включение/смену направления или заданных оборотов работающего шпинделя |
| `[time]` | `g28_time` | Секунд на кадр G28/G30 при неизвестном пути |
| `[time]` | `junction_angle` | Порог остановки на стыке в градусах, 0…180, по умолчанию 30 |
| `[mcodes]` | `M<номер>` | `класс | русское описание`; пустое значение убирает переопределение M-кода |

Классы M-кодов: `tool_change`, `program_stop`, `optional_stop`, `program_end`, `spindle_cw`, `spindle_ccw`, `spindle_stop`, `spindle_orient`, `coolant_on`, `coolant_off`, `coolant_extra`, `sub_call`, `sub_return`, `other`. Классы берутся из общей абстракции `MClass`; профиль не создаёт новый диалект.

`--wcs-offset G54=X10Y20Z-100` можно повторять для разных G54–G59. Он заменяет смещение выбранной СК целиком: незаданные оси остаются неизвестными. Нули необходимо задавать явно, например `X0Y0Z0`; нулевое смещение не подразумевается.

Полный пустой шаблон: [machines/kede-template.ini](../machines/kede-template.ini). В нём нет паспортных чисел или утверждения о совместимости KEDE с Fanuc. Модель, стойка и синтаксис реальной УП пока неизвестны; диалект остаётся выбранным через `--dialect`. Неизвестные коды дают W012. [tests/data/machine-stage11.ini](../tests/data/machine-stage11.ini) и соответствующая `.nc` — только синтетический пример для проверки, не данные реального станка.

## Пределы

W019 (`error`): эффективная рабочая подача превышает максимум. Для G95 это F×S; значения F/S проверяются также в кадрах их задания, а модальные значения — на движениях. W020 (`error`): заданные обороты превышают максимум. W021 (`error`): начало, конец, экстремумы дуги либо уровни цикла выходят за ход оси. Для XYZ используются машинные координаты при известном смещении соответствующей оси. B проверяется непосредственно в градусах, без циклического переноса ±360°.

Если смещения оси нет, суммируются её габариты в каждой рабочей СК отдельно и проверяется размах против `max-min`. W022 (`info`) явно сообщает, что абсолютные пределы не проверены. При единственной известной границе проверка размаха также невозможна. Неизвестные координаты не заменяются нулями. Длины инструмента, радиусная коррекция и преобразование XYZ при повороте B не моделируются: проверяется заданная траектория.

TXT, JSON и вкладка «Пределы станка» показывают параметр, диапазон в УП, предел, статус и строку. Нарушающие сегменты отмечаются ядром `limitViolation`; GUI использует общий `SeverityStyle` для таблиц и красной обводки, без повторного анализа УП.

## Модель времени

Старая `Report.time` и времена инструментов сохранены. Отдельная `machineTime` сравнивается с ней в TXT/JSON. Без профиля новая модель неприменима. Пустые ускорения дают **«оценка без ускорений»**; пустой профиль сохраняет прежний расчёт. Параметры смены, G28 и B не выдумываются: их отсутствие отмечается в примечаниях. Участки с неизвестной геометрией дают неполную оценку.

Скорости переводятся из мм/мин в мм/с. Для рабочего участка берётся минимум ускорений участвующих осей, для дуги — обе оси плоскости плюс движущаяся ось спирали. Если хотя бы одно нужное ускорение отсутствует, участок считается по `L/v`. С известным ускорением `a` и входной/выходной скоростью `v0/v1`:

```
vp = min(v, sqrt(a*L + (v0²+v1²)/2))
Lu = (vp²-v0²)/(2*a), Ld = (vp²-v1²)/(2*a)
t = (vp-v0)/a + (vp-v1)/a + max(0,L-Lu-Ld)/vp
```

При остановке на обоих концах: если `L >= v²/a`, трапеция `t=L/v+v/a`; иначе треугольник `t=2*sqrt(L/a)`. Это упрощённая оценка, без рывка, центростремительного ограничения скорости и многошагового look-ahead.

Для соседних рабочих сегментов сравниваются направления (у дуг — касательные). При угле больше порога скорость стыка равна нулю; иначе берётся минимум номинальных скоростей и достижимых за каждый соседний сегмент скоростей `sqrt(2*a*L)`. Дальше одного соседа планирование не идёт. Смена инструмента, остановки, выдержка, возврат, смена СК и индексирование B разрывают непрерывность; G0 и циклы считаются отдельными движениями с остановками.

G0 с заданными скоростями/ускорениями осей: отдельно рассчитывается каждое движение XYZ, время равно максимуму. Полностью пустые параметры G0 сохраняют прежнюю евклидову длину / `--rapid`. Циклы используют отдельные вертикальные подходы, рабочие ходы и возвраты; G73/G83 остаются геометрическим приближением со стружколоманием/повторным подводом. Выдержки циклов выделены в новой разбивке отдельно.

G28/G30: два ускоренных участка через промежуточную точку, рассчитанную с учётом G90/G91. Референтные точки задаются в машинных координатах; для XYZ нужны смещения СК. Если путь неизвестен, применяется `g28_time`, иначе время возврата не учитывается с явной пометкой. При известных конечных координатах они используются для следующего движения.

Смена: `tool_change` на каждую фактическую смену по профилю, с опциональным пропуском первой. Индексирование B: `abs(дельта)/90*b_seconds_per_90`; при известной промежуточной точке возврата B учитываются оба участка. Время B добавляется отдельно от XYZ: синхронное четырёхосевое резание не моделируется. G4 и выдержки циклов учитываются в секундах. M0/M1 выводятся как числа остановок без неизвестного времени оператора.
