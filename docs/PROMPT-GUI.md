# Промпт для Claude Code: этапы 6–7 (UTF-8 в консоли Windows и простое окно)

Скопируй текст ниже в Claude Code, запущенный в корне репозитория `gcode-analyzer`.

---

Ты работаешь в репозитории `gcode-analyzer` (C++20 / CMake, анализатор УП Fanuc). Этапы 1–5 уже сделаны и влиты в `main`. Теперь нужны этапы 6 и 7.

1. Прочитай `CLAUDE.md`, затем в `docs/SPEC.md` разделы 3, 6 и **полностью этапы 6 и 7** (раздел 7), затем `REPORT.md`. Строго соблюдай правила из `CLAUDE.md`.
2. Создай ветку от `main` (например `stage6-7-gui`) и работай в ней. Реализуй **по порядку**: сначала этап 6, потом этап 7. К этапу 7 переходи только когда выполнены все критерии этапа 6.
3. Этап 6 — UTF-8 в консоли Windows: `SetConsoleOutputCP(CP_UTF8)`/`SetConsoleCP` под `#ifdef _WIN32` в тонком файле CLI (не в `gca_core`), `/utf-8` для всех целей MSVC, аргументы и пути с кириллицей, сообщения CLI и `--help` на русском из одной таблицы опций, флаг `--bom`. Тесты — как в критерии этапа.
4. Этап 7 — окно на **C# WinForms, .NET 8** (`gui/GcodeAnalyzer.Gui`, `net8.0-windows`, `UseWindowsForms`, `Nullable enable`) и xUnit-тесты `gui/GcodeAnalyzer.Gui.Tests`. GUI **не** линкуется с `gca_core`: запускает собранный `gcode-analyzer.exe` дочерним процессом через `ProcessStartInfo.ArgumentList`, всегда с `--out <временный файл>`, читает отчёт как UTF-8, работает асинхронно. Сначала добавь в CLI `--machine`, `--list-options`, `--list-machines` (с тестами в `gca_tests`), потом GUI. Шпаргалку аргументов и список профилей станков GUI получает от CLI, ничего не хардкодит.
5. Владимир изучает C#: пиши GUI-код просто и идиоматично (без лишних абстракций и паттернов), с короткими комментариями **на русском** к ключевым местам (запуск процесса, async/await, drag-and-drop, разбор разделов отчёта). Форма тонкая, логика — в отдельных классах с тестами.
6. CI: GUI-зависимости в `.github/workflows/ci.yml` — добавь `actions/setup-dotnet@v4` (`8.0.x`), `dotnet build` и `dotnet test` для `gui/` на `windows-latest`; C++-задачи оставь как есть. Менять `ci.yml` здесь можно и нужно; ты пушишь с git-учёткой Владимира, это нормально. Объясни изменение в `REPORT.md`.
7. После **каждого** этапа: собери и прогони тесты (C++: `cmake --preset debug && cmake --build --preset debug && ctest --preset debug`; на Windows `cmake --preset msvc`, `cmake --build --preset msvc-debug`, `ctest --preset msvc-debug`; для этапа 7 ещё `dotnet build` и `dotnet test` по `gui/`), обнови `REPORT.md` (что сделано, результаты тестов с числами, известные проблемы), сделай коммит `stage6: ...` / `stage7: ...` и `git push` в свою ветку. Больше ничего не делай: PR не открывай, в `main` не вливай.
8. Владимир запускает тебя локально на Windows с MSVC (пресет `msvc-debug`). Поэтому на этапе 6 проверь отчёт в cmd и PowerShell без `chcp` (и путь с кириллицей), а на этапе 7 собери и **запусти** GUI локально (`dotnet run --project gui/GcodeAnalyzer.Gui`). Заполни в `REPORT.md` чек-лист ручной проверки из критерия этапа 7 и в конце попроси Владимира пройти его (открыть файл, перетаскивание, кириллица в пути, показ и разделы, сохранить txt, поле аргументов, справка по аргументам, профиль станка).
9. Пакетную обработку папки **не делай** — она в «Будущих релизах» SPEC. Если что-то в SPEC неоднозначно — прими разумное решение, запиши его в `REPORT.md` и продолжай.

Если лимит сессии заканчивается — остановись на завершённом, зелёном состоянии (сборка и тесты проходят), обнови `REPORT.md`, закоммить и запушь в ветку, чтобы следующую сессию можно было продолжить с того же места.
