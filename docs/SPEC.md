# Спецификация: gcode-analyzer

Версия спецификации: 1.0 (19.10.2026)

## 1. Назначение

Консольная утилита на C++20, которая анализирует готовые управляющие программы (УП) для ЧПУ и выдаёт текстовый отчёт. Главная цель — помочь технологу-программисту (SprutCAM) писать **постпроцессоры для новых станков**: по образцам рабочих программ понять формат кадра, структуру программы, смену инструмента, модальность, стиль комментариев и т.п.

Проект автономный, ни от чего внешнего не зависит (кроме Catch2 для тестов и, опционально, CLI11/fmt через FetchContent).

## 2. Область применения (этап 1)

- Стойка: **Fanuc**, фрезерная обработка.
- Оси: X, Y, Z; опционально 4-я поворотная ось **B** (индексная, позиционирование между проходами).
- Единицы: мм (G21 подразумевается; G20 — предупреждение «не поддерживается»).
- Архитектура должна позволять добавлять другие стойки (Siemens, Heidenhain, Haas, Mazak и т.д.) через **профиль диалекта** без переписывания ядра.
- Будущий этап (только точка расширения, без реализации): поиск значения неизвестных кодов в интернете/базе знаний для конкретной стойки.

## 3. Входные данные и CLI

```
gcode-analyzer <program.nc> [--out report.txt] [--dialect fanuc-mill] [--rapid 10000]
gcode-analyzer --help | --version
```

- Без `--out` — отчёт печатается в консоль (stdout).
- С `--out <file>` — отчёт пишется в текстовый файл (UTF-8), в консоль — только краткое сообщение.
- `--dialect` — идентификатор профиля (по умолчанию `fanuc-mill`).
- `--rapid` — скорость ускоренного перемещения G0, мм/мин (по умолчанию 10000).
- Коды возврата: 0 — успех, 1 — ошибка ввода-вывода, 2 — ошибка аргументов.
- Входной файл: ASCII, концы строк **CRLF или LF** (оба обязательно поддерживаются), может начинаться/заканчиваться `%`.

## 4. Что анализируется

### 4.1. Время обработки (оценка)
- G0: длина перемещения / скорость ускоренного хода (10000 мм/мин по умолчанию, параметр).
- G1: длина / F (мм/мин при G94).
- G2/G3: длина дуги (по I/J/K или R), включая **винтовую** интерполяцию (дуга + Z) и **полные окружности** (конечная точка = начальная, заданы только I/J — встречается в образцах при фрезеровании резьбы).
- G95 (подача на оборот): F [мм/об] × S [об/мин] → мм/мин.
- Циклы сверления G81–G89 (+G73, G76): оценка по геометрии цикла (подход ускоренно до R, рабочий ход до Z на F, возврат на R/исходную по G98/G99; для G83/G73 — учёт шагов Q приближённо).
- G4 (выдержка): P/X — добавить время.
- Смена инструмента, M0/M1, G28: время не считается (в отчёте — количество событий; позже можно задать константы в профиле).
- Модели разгона/торможения **нет** (будущий этап).
- Итог: общее время, время по каждому инструменту, разбивка G0 / рабочие / циклы.

### 4.2. Инструменты
- Список инструментов (T), факт смены (M6), **порядок использования**.
- Различать **предварительный выбор** (`T6` отдельным кадром после смены) и **фактическую смену** (`T1M6` или `M6T4`).
- Связь T ↔ H (G43 H) ↔ D (коррекция радиуса); предупреждение, если H ≠ номеру T.
- Комментарий-описание инструмента (из заголовка `( TOOL LIST: )` и из комментария после смены).

### 4.3. Рабочие системы координат
- Используемые G54–G59, G54.1 Pn (и G54 P n как вариант записи).
- Предупреждения: перемещения до назначения СК; «G54.1 P0»/нулевое смещение вместо G54; смена СК внутри работы инструмента; разные СК у разных инструментов (информационно).

### 4.4. Подачи и обороты
- По каждому инструменту: min/max F (отдельно для G94 и G95), min/max S, направление шпинделя (M3/M4), охлаждение (M7/M8/M9 и машинно-специфичные).
- S может быть дробным (`S5305.165` в образце) — парсить как double, в отчёте отметить.

### 4.5. Габариты траектории (bounding box)
- Общий и по каждому инструменту: X/Y/Z min/max, диапазон B.
- Учитывать G90/G91. Перемещения G28 (возврат в референтную точку) **не** включать в габарит рабочей СК (позиция в машинных координатах неизвестна) — после G28 координата оси помечается как «неизвестна» до следующего абсолютного задания.
- Отдельно габарит рабочих ходов (G1/G2/G3/циклы) и с учётом G0.

### 4.6. Статистика кодов
- Все G-коды и M-коды с количеством, сортировка по номеру; для каждого — краткое описание из профиля диалекта; неизвестные коды помечаются `?` (кандидаты для будущего онлайн-поиска).

### 4.7. Циклы сверления
- G81–G89, G73, G76: количество отверстий по каждому циклу и инструменту, параметры (Z, R, Q, P, F), режим возврата G98/G99, отмена G80.

### 4.8. Предупреждения (warnings)
Примеры (список расширяемый):
- нет рабочей СК до первого перемещения; G54.1 P0 / смещение 0;
- рабочий ход без S или шпиндель не включён (нет M3/M4);
- G1/G2/G3 без F;
- G43 без H или H ≠ T;
- смена инструмента без отмены коррекции радиуса (G40);
- G41/G42 активна при G0;
- G91 остаётся активным после G28 (опасная модальность — в образцах `G91 G28 ...` и затем явный `G90`);
- цикл не отменён G80 до смены инструмента;
- неизвестные G/M-коды; неразобранные слова; G20 (дюймы).

Каждое предупреждение: номер строки, текст кадра, код предупреждения, сообщение.

### 4.9. Шпаргалка для постпроцессора («Postprocessor cheat-sheet»)
Отдельный раздел отчёта, выведенный **из анализа**, а не захардкоженный:
1. **Структура программы**: начало (`%`, `O…`, комментарии с именем/датой, список инструментов, безопасная строка), последовательность смены инструмента (кадры между окончанием одного инструмента и первым рабочим ходом следующего — показать «шаблон» с подстановками `<T>`, `<H>`, `<S>`), конец программы.
2. **Формат кадра**: нумерация N (есть/нет, где именно, шаг, связь N с номером инструмента), типичный порядок слов в кадре, количество знаков после запятой по адресам, точка у целых значений (`Z32.` vs `Z0`), ведущие нули, пробелы между словами, регистр.
3. **Модальность**: какие слова повторяются в каждом кадре, какие опускаются (G1, F, координаты без изменения).
4. **Комментарии**: стиль `( ... )`, транслитерация, верхний регистр, пробелы внутри скобок.
5. **Поворот B**: как программируется (отдельный кадр, вместе с G0, с зажимом/разжимом M-кодами и т.д.). Если B не встречается — явно написать «ось B в программе не используется».
6. **Машинно-специфичные коды**: G05.1, G08, M15, M53 и т.п. — где стоят в структуре.

## 5. Факты о формате, найденные в образцах

Образцы лежат в `samples/` (рабочие программы из реальных проектов, **менять нельзя**; `.gitattributes` защищает их от конвертации концов строк):

| Файл | Станок | Строк | Размер |
|---|---|---|---|
| `sample-01-skymaster-vl1100a.nc` | Sky Master VL1100A | 4971 | 114 949 б |
| `sample-02-bridgeport-1300-480.nc` | Bridgeport 1300/480 3-Axis | 3626 | 64 672 б |

Общее:
- Концы строк **CRLF**, только ASCII, комментарии в транслите (`TOROIDALNAYA FREZA`), верхний регистр.
- Начало: строка `O` **без номера**, затем `(name_project)`, `(DATE: …)`, `(TIME: …)`, `( === Generated for <станок> === )`, `( TOOL LIST: )` с `( Tn: описание )` — **с повторами** (по каждой операции, а не уникальный список). `%` только в конце файла (после `M30`).
- Безопасная строка в начале: `G64 G0 G91 G28 Z0`, `G91 G28 Y0` (во 2-м образце ещё `G91 G28 X0`), `G80 G94 [G64] G40 G49`.
- Смена инструмента:
  - образец 1: `T1M6`, затем предварительный выбор следующего `T3` отдельным кадром;
  - образец 2: `M6T4`, затем `T6` (предвыбор).
  - Между операциями одним инструментом смены нет, но есть `T<след.>` и блок возврата.
  - Шаблон после смены: `(описание инструмента)`, [`G0 G64`, `G08P1`, `G05.1Q1`], `G90 G54 G94 [G64] G17 X… Y…`, `M1`, `G43 Z… Hn Dn S… M3`, подход по Z, `M8` (или `M8` в кадре с G1/циклом).
  - Окончание инструмента: `G0 Z…`, `M9`, `(комментарий следующей операции)`, `G0 M5`, `N<номер>`, [`G05.1Q0`, `G08P0`], `G91 G28 Z0.`, `G91 G28 Y0` [`G91 G28 X0`], `G49 H0`, `M1`.
- Нумерация N: **только** в начале операции (8 кадров на файл); номер N обычно равен номеру следующего инструмента (`N3`, `N6`, `N11`, `N14`), но встречается и `N130` — правило определять анализом, не хардкодить.
- `M0` в середине программы с парковкой (`X-250. Y200. Z300.`, `M5`, `M0`) — остановка оператора между операциями.
- Конец: `M9`, `M5`, [`G05.1Q0`, `G08P0`], `G91 G28 Z0.`, `G91 G28 Y0.`, `G90 G49 H0`, `M30`, `%`.
- Точность: до 3 знаков после запятой; у целых — точка (`Z32.`, `X-4.`), **кроме** нулей в G28 (`Z0`, `Y0`, иногда `Z0.`) — непоследовательно.
- Модальность: G1/G2/G3 и F опускаются, пока не меняются; координаты — только изменившиеся; F часто стоит в кадре с G1 при врезании.
- Дуги: только **I/J** (R не используется), `I0.` записывается явно; много **винтовых** дуг (`G3 X… Y… Z… I… J…`) и **полных окружностей** с Z (`G2 Z-0.5 I0.2 J0.`) — резьбофрезерование.
- Коррекция радиуса: `G41`/`G42` в отдельных кадрах с координатой, `G40` в кадре `G1 G40 X…`; D задаётся в кадре G43 (`H1 D1`).
- Циклы: `G98 G95 [G17] G81 Z… R… F0.05 [M8]` и `G83 Z… R… Q… F…`; подача **на оборот G95** в циклах, после — возврат к G94; каждое отверстие оформлено как `G80` → перемещение `X…/Y…` → повтор `G81 Z… R… F…` (цикл повторяется полностью, а не модально).
- `G1 G95 Z… F0.11` — подача на оборот и для фрезерования резьбы.
- Обороты: `S4200`, `S8000`, а также дробное `S5305.165`.
- Ось **B в образцах не встречается** (оба — 3-осевые программы). Поддержку B проектировать по спецификации, проверять на синтетических тестах.
- Машинно-специфичные коды: `G05.1Q0/Q1` (AI-контурное управление/предпросмотр), `G08P0/P1` (предпросмотр), `G64` (режим резания), `M15` (обр. 1, 29 раз, после подвода по Z — значение по документации станка неизвестно), `M53` (обр. 2, 1 раз). Неизвестные — помечать `?`.
- Записи без пробела между словами: `G05.1Q0`, `G08P0`, `T1M6`, `M6T4` — лексер обязан это поддерживать. Встречаются хвостовые пробелы (`M5 `, `M0 `).
- Статистика (для ориентира): обр. 1 — G1:1179, G3:852, G2:192, G0:181, G81:42, G83:12, инструменты T1,T3,T6,T11,T4,T7,T6,T7; обр. 2 — G1:918, G2:570, G42:570, G3:304, G0:61, G81:14, G83:14, инструменты T4,T6,T12,T8,T6,T14,T15.

## 6. Архитектура (модули)

Все модули — в библиотеке `gca_core` (`include/gca/`, `src/`); `main.cpp` — тонкий CLI.

1. **Lexer / Tokenizer** (`lexer.hpp`): строка → `Block { lineNo, raw, optional<N>, vector<Word{letter, value, rawText}>, vector<Comment>, blockDelete }`. Хранит исходный текст слова (`rawText`) — нужен для анализа формата (точка, число знаков, ведущие нули). Поддержка: слова без пробелов, `G05.1`, комментарии `(...)` и `;`, `%`, `O`, `/`, CRLF/LF, пустые строки. Ошибки — в список диагностик, не исключения.
2. **Dialect profile** (`dialect.hpp`): интерфейс `IDialect` — модальные группы G-кодов, описания G/M, какие коды означают смену инструмента, СК, циклы, ускоренный ход, оси (линейные/поворотные), правила тонкостей (например, `M6T4` vs `T1M6`). Реализация `FanucMillDialect`. Реестр диалектов по id (`--dialect`). Данные по возможности табличные (constexpr-таблицы или встроенный текстовый ресурс), чтобы позже грузить из файла.
3. **Code knowledge provider — точка расширения** (`knowledge.hpp`): интерфейс `ICodeKnowledgeProvider { optional<CodeInfo> lookup(dialectId, code) }`. Цепочка провайдеров: встроенная таблица профиля → (будущее) локальный кэш → (будущее) онлайн-поиск. Сейчас реализуется только встроенный провайдер; онлайн — **не реализовывать**, только интерфейс и заглушка.
4. **Modal state machine** (`modal_state.hpp`): текущее состояние — группы движения (G0/1/2/3/циклы), плоскость, G90/G91, G94/G95, СК, коррекции (G41/42/40, G43/49), активный T, предвыбранный T, S, F, шпиндель, охлаждение, позиция (с флагом «неизвестна» по осям), параметры цикла. Применение кадра → событие(я).
5. **Motion / time calculator** (`motion.hpp`): из событий движения — сегменты (`Linear`, `Arc` с центром/радиусом/углом/высотой спирали, `CycleHole`), длины и время. Геометрия дуг — отдельные чистые функции (тестируются отдельно).
6. **Analyzers** (`analyzers/*.hpp`): наблюдатели (`IAnalyzer { onBlock, onSegment, onToolChange, finish }`), каждый отвечает за свой раздел: время, инструменты, СК, подачи/обороты, габариты, статистика кодов, циклы, предупреждения, формат (cheat-sheet). Новые анализаторы добавляются без изменения ядра.
7. **Report writer** (`report.hpp`): модель отчёта (структуры) отделена от форматирования; `TextReportWriter` пишет в `std::ostream` (консоль или файл). Позже возможен JSON/Markdown.
8. **CLI** (`main.cpp`): разбор аргументов, выбор вывода, коды возврата.

Принципы: RAII, без сырых `new/delete`, `std::string_view` для разбора, без глобального состояния, без зависимостей от ОС (только `std::filesystem`), числа парсить локале-независимо (`std::from_chars`; для MSVC/GCC — проверить поддержку double, иначе своя реализация).

## 7. Этапы и критерии приёмки

Каждый этап: сборка без предупреждений на GCC/Clang/MSVC (по возможности), все тесты зелёные, CI зелёный, обновлён `REPORT.md`.

### Этап 1 — Лексер и модальное состояние
- Лексер разбирает оба образца без ошибок; юнит-тесты на: слитные слова (`G05.1Q0`, `M6T4`), комментарии, CRLF/LF, `%`, `O`, `N`, отрицательные/дробные значения, `Z32.`, сохранение `rawText`.
- Профиль `fanuc-mill` с модальными группами и описаниями основных G/M.
- Модальная машина: G90/G91, G94/G95, плоскость, СК, T/M6/предвыбор, S/F, позиция.
- Отчёт: статистика G/M-кодов с количеством; список инструментов в порядке использования.
- **Критерий**: для образцов счётчики G0/G1/G2/G3/G81/G83 совпадают с разделом 5 (тест); последовательности инструментов совпадают с разделом 5 (тест).

### Этап 2 — Геометрия, время, габариты
- Длины линейных/дуговых/винтовых/полных окружностей; циклы; G95→мм/мин.
- Время общее и по инструментам; габариты общий/по инструменту, B-диапазон.
- **Критерий**: юнит-тесты геометрии (четверть окружности R10 = 15.708 мм ±1e-3, полная окружность, спираль), синтетическая программа с известным временем (±0.5%), габариты синтетики точно; образцы обрабатываются, время > 0, без исключений.

### Этап 3 — СК, подачи/обороты, циклы, предупреждения
- Разделы 4.3, 4.4, 4.7, 4.8.
- **Критерий**: синтетические тесты на каждое предупреждение (срабатывает / не срабатывает); в образцах обнаружены G54, циклы G81/G83 с количеством отверстий, M15/M53 — в списке неизвестных/машинно-специфичных.

### Этап 4 — Шпаргалка для постпроцессора
- Раздел 4.9, выведенный из анализа.
- **Критерий**: для образцов корректно определены: N только в начале операций, разный порядок `T1M6` / `M6T4`, предвыбор следующего T, точка у целых, 3 знака, I/J без R, CRLF, отсутствие оси B; шаблон смены инструмента выводится с подстановками.

### Этап 5 — CLI и финальный отчёт
- `--out`, `--dialect`, `--rapid`, `--help`, `--version`, коды возврата; golden-тесты отчёта по образцам (сравнение с эталоном в `tests/golden/`, эталон обновляется осознанно).
- **Критерий**: `gcode-analyzer samples/sample-01-skymaster-vl1100a.nc --out r.txt` создаёт полный отчёт со всеми разделами; CI зелёный на ubuntu и windows.

### Будущее (не делать сейчас)
- Другие стойки (Siemens 840D, Heidenhain, Haas…) — новые профили.
- Онлайн-поиск значений кодов (реализация `ICodeKnowledgeProvider`), кэш.
- Модель разгона/торможения, параметры станка в профиле.
- Поддержка 5 осей, G68.2, токарной обработки, макропрограмм (#, IF, GOTO, WHILE).
