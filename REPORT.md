## Что сделано
Вся логика в библиотеке `gca_core`, `src/main.cpp` вызывает только `gca::runCli`.

- Этап 1. Лексер (`lexer.hpp`): `Block` / `Word` с `rawText`, смещением и признаком пробела перед словом, комментарии `(...)` и `;`, `%`, `O` без номера, `N`, `/`, CRLF/LF/смешанные концы строк, слитные слова (`G05.1Q0`, `T1M6`, `M6T4`). Числа разбираются собственной локале-независимой `parseNumber` (без `std::from_chars` для double, чтобы не зависеть от версии MSVC). Ошибки идут в `Program::diagnostics`, исключений нет. Профиль диалекта (`dialect.hpp`): `IDialect`, `FanucMillDialect` (таблицы G/M с модальными группами, классами и описаниями по-русски), реестр `findDialect`, `Profile` = диалект + профиль станка. Профили станков выбираются по комментарию `Generated for ...`: Sky Master VL1100A (M15, доп. СОЖ) и Bridgeport 1300/480 (M53, СОЖ через шпиндель). Точка расширения `ICodeKnowledgeProvider` (`knowledge.hpp`): встроенный провайдер, заглушка онлайн-поиска (всегда пусто), цепочка `KnowledgeChain`. Модальная машина (`modal_state.hpp`): G0..G3 и циклы, плоскость, G90/G91, G94/G95, СК (G54-G59, `G54.1 Pn`, `G54 Pn`), G40/41/42, G43/G49, T/M6/предвыбор, S, F, шпиндель, СОЖ, позиция с флагом «неизвестна».
- Этап 2. `motion.hpp`: геометрия дуг (I/J/K или R, знак R, полные окружности, винтовые дуги, точные границы дуги), перевод подачи (G94, G95 = F x S), длины и время сегментов, циклы по геометрии. `TimeAnalyzer` (G0 / рабочее / циклы / выдержки, всего и по инструментам), `BBoxAnalyzer` (все перемещения и рабочие ходы, общий и по инструментам, диапазон B, G28/G53 не входят).
- Этап 3. `WcsAnalyzer`, `FeedsSpeedsAnalyzer`, `CyclesAnalyzer`, `WarningsAnalyzer` (W001..W018, список кодов в `analyzers/warnings.hpp`).
- Этап 4. `FormatAnalyzer`: шпаргалка из шести разделов (структура, формат кадра, модальность, комментарии, ось B, машинно-специфичные коды), всё выводится из текста программы. Шаблон смены инструмента строится по всем сменам файла, значения заменены подстановками, у каждой строки указано, в скольких сменах она встречается.
- Этап 5. CLI (`cli.hpp`, `cli.cpp`): `--out`, `--dialect`, `--rapid`, `--help`, `--version`, коды возврата 0/1/2. Отчёт: `report.hpp` (модель) и `writeTextReport` (UTF-8, `\n`). Golden-тесты отчётов (`tests/golden/`), синтетические программы в `tests/data/`.

## Как собрать и запустить
Как в `CLAUDE.md`:
```bash
cmake --preset debug && cmake --build --preset debug && ctest --preset debug
./build/debug/gcode-analyzer samples/sample-01-skymaster-vl1100a.nc --out report.txt
```
Эталоны отчётов обновляются осознанно: создать пустой файл `tests/golden/UPDATE`, запустить `gca_tests`, удалить файл, посмотреть `git diff tests/golden`.

## Известные проблемы и ограничения
Решения по неоднозначным местам SPEC:
- После `G80` группа 01 считается равной `G0` (как у Fanuc), поэтому `X.. Y..` после `G80` это ускоренное перемещение.
- `G4`: `X` всегда секунды; `P` без десятичной точки миллисекунды, с точкой секунды (Fanuc).
- Позиция по оси после `G28` неизвестна, пока ось не задана абсолютно. Ход из неизвестной точки (первый подвод после G28) в длину по неизвестным осям не входит; их число выводится в отчёте (образец 1: 18). Это занижает время на несколько подходов.
- Время G0 считается по евклидовой длине на одной скорости, без раздельных скоростей осей и без разгона/торможения. Смена инструмента, M0/M1, G28 по времени не считаются.
- Перемещения оси B в длину и время не входят (индексная ось, время поворота позже задавать в профиле станка); диапазон B в габарите есть.
- Циклы: G83 приближённо (отвод в R на каждом шаге Q, зазор 1 мм), G73 (отвод 1 мм), G82/G89/G88 добавляют выдержку P (мс), G84/G74/G85/G89 выходят на рабочей подаче. Подача цикла в G95 это F x S.
- Габарит: учитываются только заданные координаты в рабочей СК; парковка `X-250. Y200. Z300.` входит в габарит всех перемещений, но не в габарит рабочих ходов.
- Предупреждения: W003 (смена СК внутри операции) срабатывает на смену СК после первого перемещения текущего инструмента; W004/W005/W009 выдаются один раз на операцию (между двумя M6); W010 срабатывает на перемещение в G91 после G28 и на конец программы в G91; допуск разницы радиусов дуги для W018 равен 0.02 мм; неизвестные коды группируются по коду (первая строка + число вхождений).
- Профили станков определяются по подстроке в комментарии `Generated for ...`; для других станков M15/M53 и им подобные будут помечены `?`.
- Дробные S парсятся как double, в отчёте отмечено «есть дробные значения S».
- Шпаргалка: шаблон смены строится по строкам, не по смыслу; при сильно разных сменах основной шаблон берёт строки из ≥50% смен, остальные выводятся отдельным списком. Правило связи N с инструментом выводится как «N = инструмент следующей операции» и сопровождается списком исключений.
- Golden-тесты сравнивают отчёт целиком: числа выводятся с 1-3 знаками, расхождение libm между платформами в последнем разряде может теоретически изменить округление; на Linux стабильно. Если CI на Windows покажет расхождение, эталон надо смотреть осознанно, а не обновлять автоматически.
- Отчёт на русском в UTF-8: в консоли Windows нужна кодовая страница 65001 или `--out`.
- Не реализовано по SPEC (раздел «Будущее»): другие стойки, онлайн-поиск кодов (есть только интерфейс и заглушка), модель разгона, 5 осей, макропрограммы, токарная обработка, G20 (только предупреждение W014).
