# CLAUDE.md — правила работы для Claude Code

Проект: **gcode-analyzer** — анализатор УП Fanuc (фрезерование, 3 оси + индексная B) для разработки постпроцессоров. Язык общения и документации — **русский**; идентификаторы и комментарии в коде — на английском.

## 1. Перед началом работы
1. Прочитай **`docs/SPEC.md` целиком** — это источник истины (требования, факты о формате образцов, модули, этапы и критерии приёмки).
2. Прочитай `REPORT.md` — что уже сделано и какие известны проблемы.
3. Работай **по этапам** из `docs/SPEC.md` раздел 7, по порядку. Не перескакивай, пока критерии текущего этапа не выполнены.

## 2. Сборка и тесты

Linux / macOS (GCC или Clang, Ninja):
```bash
cmake --preset debug
cmake --build --preset debug
ctest --preset debug
```

Windows (MSVC, Visual Studio 2022):
```bat
cmake --preset msvc
cmake --build --preset msvc-debug
ctest --preset msvc-debug
```

Запуск:
```bash
./build/debug/gcode-analyzer samples/sample-01-skymaster-vl1100a.nc
./build/debug/gcode-analyzer samples/sample-01-skymaster-vl1100a.nc --out report.txt
```

## 3. Обязательный цикл
- **После каждого изменения** — собрать и запустить тесты.
- Если сборка или тесты красные — **чини, пока не станет зелёным**. Не отключай и не ослабляй тесты, чтобы «пройти».
- Новый функционал — с юнит-тестами (Catch2, `tests/`). Для геометрии и времени — тесты с известным ответом.
- Сборка без предупреждений (`-Wall -Wextra -Wpedantic -Wconversion -Wshadow`, `/W4`).

## 4. Ограничения
- **Не изменяй файлы в `samples/`** (ни содержимое, ни концы строк CRLF). Новые тестовые программы — в `tests/data/`.
- **Кроссплатформенность**: C++20 стандартной библиотеки, `std::filesystem`, никаких POSIX/WinAPI-зависимостей, никаких расширений компилятора. Проверяй, что код собирается MSVC (осторожно с `std::from_chars` для double, `<format>`, неявными сужающими преобразованиями).
- Зависимости — минимум: Catch2 (уже есть), опционально CLI11 и fmt через `FetchContent`. Ничего не ставить в систему.
- Логика — в библиотеке `gca_core`; `main.cpp` — тонкий CLI.
- Профиль диалекта — через абстракцию (`IDialect`), без хардкода Fanuc в ядре. Онлайн-поиск кодов — **только интерфейс**, не реализовывать.
- Не трогай другие репозитории; не меняй `.github/workflows/ci.yml` без необходимости (если меняешь — объясни в `REPORT.md`).

## 5. В конце работы (каждой сессии / этапа)
1. Обнови **`REPORT.md`**: что сделано; как собрать; результаты тестов **с числами** (сколько тест-кейсов/assertions прошло, вывод `ctest`); известные проблемы; следующие шаги.
2. Коммиты — небольшие, с понятными сообщениями на английском или русском (`stage1: lexer with glued words support`).
3. `git push` в `main` (или в ветку, если так попросили). Проверь, что CI зелёный, если есть доступ к `gh`.
